# Meow Dashboard — v1.0.0 기획서

> 회사 업무를 원활하게 처리하기 위한 개인용 대시보드
> **v1.0.0 목표**: `Team-AIVN` 오가니제이션에서 나에게 리뷰 요청된 PR 목록을 한눈에 확인

---

## 1. 배경 및 목적

### 배경
- 하루에도 여러 리포지토리에서 리뷰 요청이 들어오고, GitHub 알림/이메일에 묻혀 놓치는 경우가 발생함
- GitHub 웹의 "Review requests" 화면은 필터·정렬이 부족하고, 다른 업무 정보와 함께 볼 수 없음

### 목적
- 나에게 리뷰가 요청된 PR을 **한 페이지**에서 빠르게 파악
- 이후 버전에서 확장할 개인 업무 대시보드의 **기반(Foundation)** 마련

### 성공 지표 (v1.0.0)
- 대시보드 진입 후 **3초 이내**에 내가 리뷰해야 할 PR 목록이 렌더링됨
- PR을 놓쳐서 리마인드를 받는 횟수가 도입 전 대비 감소
- 매일 최소 1회 이상 자연스럽게 사용

---

## 2. 범위

### In Scope (v1.0.0)
- `Team-AIVN` 오가니제이션 내 모든 리포지토리 대상
- **내(로그인 사용자)가 리뷰어로 지정된** Open 상태 PR 목록 조회
- PR 카드에 다음 정보 표시
  - 리포지토리 이름
  - PR 제목 / 번호
  - 작성자 (아바타 + 이름)
  - 생성일 / 마지막 업데이트일 (상대시간, 예: "2시간 전")
  - Draft 여부
  - CI 상태 (성공 / 실패 / 진행중)
  - 라벨
- PR 카드 클릭 시 GitHub PR 페이지 새 탭 열기
- 목록 수동 새로고침 버튼
- GitHub OAuth 또는 Personal Access Token(PAT) 기반 인증

### Out of Scope (v1.0.0에서 하지 않음)
- 내가 **작성한** PR 목록 (v1.1에서 검토)
- 이슈, 알림, 커밋 등 PR 이외의 리소스
- PR 승인/코멘트 등 **쓰기(write) 액션**
- 팀 단위 리뷰 요청 (개인 지정만 처리)
- 다중 오가니제이션 지원
- 모바일 반응형 (데스크톱 우선)
- 다크모드 (v1.1에서 검토)

## 3. 사용자 시나리오

### Persona
- 나 자신 (Team-AIVN 소속 개발자)

### Primary Flow
1. 아침에 출근하여 대시보드를 연다
2. 상단에 "리뷰 대기 중인 PR N건"이 보인다
3. 오래된 PR부터 정렬되어 있어 우선순위를 판단한다
4. 카드를 클릭해 GitHub에서 리뷰를 진행한다
5. 리뷰 완료 후 새로고침하여 목록이 줄어듦을 확인한다

### Edge Cases
- 리뷰 요청 PR이 0건일 때 → "모두 처리했습니다" 형태의 빈 상태 UI
- GitHub API rate limit 초과 → 남은 쿼터와 리셋 시각 안내
- 토큰 만료 / 권한 부족 → 재인증 유도 화면
- 네트워크 오류 → 마지막 성공 데이터 + 재시도 버튼

## 4. 화면 구성

### 4.1 헤더
- 좌: 서비스명 "Meow"
- 우: 로그인 사용자 아바타, 마지막 동기화 시각, 새로고침 버튼

### 4.2 PR 목록 섹션
```
┌─────────────────────────────────────────────────┐
│  리뷰 대기 PR (N)              [정렬 ▾] [새로고침] │
├─────────────────────────────────────────────────┤
│ [Repo]  PR #123 · Feat: xxxxxxxx                │
│         @author · 2일 전 업데이트                 │
│         [Draft] [CI ✅] [label] [label]           │
├─────────────────────────────────────────────────┤
│ ...                                              │
└─────────────────────────────────────────────────┘
```

### 4.3 정렬 옵션
- 오래된 순 (기본)
- 최신 순
- 리포지토리별

### 4.4 빈 상태 / 오류 상태
- Empty: "리뷰 요청이 없습니다 🎉"
- Error: 오류 메시지 + 재시도

| F-08 | 마지막 동기화 시각 표시 | Should |

## 6. 기술 스택 (제안)

- **프론트엔드**: Next.js (App Router) + TypeScript + Tailwind CSS
- **데이터 페칭**: TanStack Query + GitHub REST/GraphQL API (Octokit)
- **인증**: GitHub OAuth App (또는 PAT를 로컬 저장) — 개인용이므로 v1.0.0은 **PAT 우선** 고려
- **배포**: Vercel (개인용, 무료 티어)
- **로컬 저장**: 토큰은 브라우저 `localStorage` 또는 서버 세션

### GitHub API 쿼리 예시
```graphql
query {
  search(
    query: "org:Team-AIVN is:pr is:open review-requested:@me"
    type: ISSUE
    first: 50
  ) {
    nodes {
      ... on PullRequest {
        number
        title
        url
        isDraft
        createdAt
        updatedAt
        author { login avatarUrl }
        repository { nameWithOwner }
        labels(first: 10) { nodes { name color } }
        commits(last: 1) {
          nodes {
            commit { statusCheckRollup { state } }
          }
        }
      }
    }
  }
}
```

## 7. 비기능 요구사항

- **성능**: 최초 로딩 3초 이내
- **보안**: 토큰은 클라이언트 저장 시 최소 권한(`repo:read`, `read:org`) PAT 사용 권장
- **개인정보**: 개인용 로컬 사용이 원칙, 외부 로깅/트래킹 없음
- **접근성**: 키보드 네비게이션 지원
